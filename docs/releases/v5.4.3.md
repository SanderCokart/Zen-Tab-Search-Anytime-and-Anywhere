  <strong>Folders fill up again.</strong><br />
  Agents can open tabs into folders and pin tabs, as 5.4.2 meant them to.

## Bug fixes

<details>
<summary><strong><code>zen_apply_patch</code> opens tabs into folders again.</strong> New tabs no longer fail with <code>setTimeout is not defined</code>.</summary>

5.4.2 waits for a newly pinned tab to load before it stores the tab's pinned URL. That wait used a timer that does not exist in Zen's privileged scope, so pinning a new tab threw. Every new tab opened into a folder failed and was closed again, and so did every tab the patch asked to pin. The wait now uses the window's own timer, so the tabs open, pin and store the page they load, without the "changed" slash.
</details>

A patch that failed on 5.4.2 may have left an empty folder behind. Pass that folder's `id` when you run the patch again, or it creates a second folder with the same name.

## Install or update

**On 5.4.x:** open the deck and choose **Install now** on the update notice.

**Anywhere else:** download [`zen-deck-v5.4.3-firefox.zip`](https://github.com/SanderCokart/Zen-Deck/releases/download/v5.4.3/zen-deck-v5.4.3-firefox.zip) and install it from `about:addons` → ⚙ → **Install Add-on From File…**. Coming from 4.x, see the [5.0.0 notes](https://github.com/SanderCokart/Zen-Deck/releases/tag/v5.0.0) first.

The bridge protocol is still version 8, so 5.4.2's [`zen-deck-mcp.mjs`](https://github.com/SanderCokart/Zen-Deck/releases/download/v5.4.3/zen-deck-mcp.mjs) keeps working. The fix is in the extension.
