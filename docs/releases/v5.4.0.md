## Prefix cheat-sheet

The search field has a `?` on the right. Rest on it and a legend prints the prefixes that jump columns and the `-` exclude, with usage examples below them.

`@` is omitted when todos are off. `#` and `!` are omitted when forge detection is off. `-` is always there.

![The search field with the prefix legend printed](https://raw.githubusercontent.com/SanderCokart/Zen-Deck/v5.4.0/docs/screenshots/dark/search-query-help.png)

*`?` next to Search. `@`, `#`, `!` and `-` with examples.*

## Hide matches with `-word`

A token that starts with `-` is an exclude, not an include. `auth -gitlab` keeps tabs that match auth and drops any whose title, label, folder, space or host has that word.

`-draft` hides a Draft: merge request. It does not hide a tab because `draft` appears inside another word, in the GitLab URL path, or only in leftover page-title chrome after you renamed the tab.

A leading `-gitlab` hides those matches with no include term. Chain them: `-draft -wip`. A lone `-` does nothing until you type a word. Hyphenated titles typed without a space (`foo-bar`) stay includes.

The exclude also applies to the issue navigator.

![Typing -gitlab until the GitLab issue leaves the list](https://raw.githubusercontent.com/SanderCokart/Zen-Deck/v5.4.0/docs/gifs/query-exclude.gif)

*`-gitlab` in Simple. The GitLab issue drops; the GitHub PR stays.*

## Mark done and close

**Clear…** on the todo column is a menu with two groups: **Mark done** and **Mark done and close**. Each has All, Red, Orange and Green, with a count.

Pick a row and a confirm well asks. Mark done stays quiet. Done & close is red. Cancel leaves the todos.

![The Clear menu with Mark done and Mark done and close](https://raw.githubusercontent.com/SanderCokart/Zen-Deck/v5.4.0/docs/screenshots/dark/todo-clear-menu.png)

*Clear…. Two groups. Green is empty here, so it is dimmed.*

## Features

<details>
<summary><strong>Prefix cheat-sheet.</strong> A <code>?</code> key next to search prints <code>@</code>, <code>#</code>, <code>!</code> and <code>-</code> with usage examples.</summary>

The list follows the complexity flags: no todos means no <code>@</code>. No forge detection means no <code>#</code> or <code>!</code>.
</details>

<details>
<summary><strong>Hide matches with <code>-word</code>.</strong> A token that starts with a minus drops matching tabs, issues and requests.</summary>

<code>auth -gitlab</code> keeps auth. Chain them: <code>-draft -wip</code>. The minus matches a whole word on the visible name or host, not a substring and not the GitLab path. A lone <code>-</code> does nothing until you type a word. <code>foo-bar</code> is still one word.
</details>

<details>
<summary><strong>Mark done and close.</strong> Clear… can mark todos done and close those tabs.</summary>

Two groups in the menu. Confirm copy changes, and the commit key turns red when close is on.
</details>

<details>
<summary><strong>Enhanced without grids.</strong> Spaces and essentials stay off on Enhanced. Folder grouping and the context menu come on.</summary>

The compact overlay stays a centred card. Timers, copy link and reuse-an-open-tab are unchanged.
</details>

<details>
<summary><strong>Pro without MCP or the status bar.</strong> Pro keeps todos and status colours. The MCP module and the always-on footer wait for Dev.</summary>

The bar still shows when an update is available, on every preset.
</details>

<details>
<summary><strong>Context menu follows complexity.</strong> Todo, copy link, timer, status and host overrides leave the context menu when those flags are off.</summary>

They are hidden, not greyed out. After <strong>Mark as todo</strong>, the context menu stays open so a status colour can still be set.
</details>

## Bug fixes

<details>
<summary><strong>Caret in the search field.</strong> Left and Right move the cursor. Skip five rows with Ctrl+Up and Ctrl+Down.</summary>

Left and Right used to jump five tabs, so the caret in the query could not move.
</details>

<details>
<summary><strong>Disabled context menu items.</strong> Actions the Complexity flags turned off no longer appear in the context menu.</summary>

They used to sit in the context menu as if they still did something.
</details>

<details>
<summary><strong>Context menu after Mark as todo.</strong> Right-click, mark a todo, then set a colour without opening the context menu twice.</summary>

The context menu used to close on the todo action.
</details>

## Cosmetic changes

<details>
<summary><strong>Fill slider.</strong> The Complexity rail fills to the thumb, so the stop is easier to read.</summary>
</details>

<details>
<summary><strong>Settings popup.</strong> 460×620, and it resizes back to that when it is focused.</summary>

Complexity stays one column at that width.
</details>

<details>
<summary><strong>Todo lamp after the meta.</strong> On tab rows and in the issue navigator, the todo marker sits after the host, not before the title.</summary>
</details>

## Install or update

**On 5.3.0:** open the deck and choose **Install now** on the update notice.

**Anywhere else:** download [`zen-deck-v5.4.0-firefox.zip`](https://github.com/SanderCokart/Zen-Deck/releases/download/v5.4.0/zen-deck-v5.4.0-firefox.zip) and install it from `about:addons` → ⚙ → **Install Add-on From File…**. Coming from 4.x, see the [5.0.0 notes](https://github.com/SanderCokart/Zen-Deck/releases/tag/v5.0.0) first.

The matching MCP server is [`zen-deck-mcp.mjs`](https://github.com/SanderCokart/Zen-Deck/releases/download/v5.4.0/zen-deck-mcp.mjs).
